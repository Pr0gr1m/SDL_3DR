TL;DR

  • Five decision areas, 4 alternatives each: measurement, CPU cache, GPU mesh ownership, hidden-face/meshing, chunk data layout.
  • Recommended: Release + frame-time stats; replace the CPU Face cache with dirty-flag meshes; per-chunk persistent GPU buffers; neighbor-aware face culling; keep data layout for now.
  • Order: measure → invalidation/mesh ownership → per-chunk GPU buffers → neighbor culling → layout only if measured.
  • Confidence medium: static research only, nothing profiled.

Key Decisions

  • Area 1: Release build + in-app per-stage timers (roadmap item; a learning goal in itself).
  • Area 2: Remove the CPU Face cache; use a per-chunk dirty flag (cache is in the wrong layer, F1-F3, F5).
  • Area 3: Per-chunk persistent GPU vertex buffers, rebuilt only when dirty.
  • Area 4: Neighbor-aware cross-chunk culling; defer greedy meshing and indexing.
  • Area 5: Keep std::optional<Object> until memory or gen time is measured to matter.

Open Questions / Risks

  • All magnitudes unmeasured; if Release is GPU-bound or fast, Areas 3-5 lose urgency (Area 1 gates them).
  • Cross-chunk culling needs neighbor dirtying on edit and a policy for unloaded neighbors (air vs solid).
  • Thread safety of E-key edits vs parallel render is unverified.
  • Toolchain mismatch (MinGW logs vs MSVC-triplet vcpkg) may mean the real build differs from the analyzed one.

Problem Reframing

The only cache (Chunk::cache) is inverted (App.cpp:1418), never invalidated (1550) and stores a camera-dependent frustum-culled subset; on a hit the frame still copies, flattens, regenerates vertices and re-uploads everything (1396, 1587-1681). Face culling is off (chunkFaceCulling=false) and no optimization flags exist. Scope: HOW to close these gaps, not new features.

HMW: (1) get trustworthy numbers; (2) make "unchanged chunk means no work" correct; (3) stop re-uploading the whole scene; (4) stop generating never-visible faces; (5) keep per-block cost proportional to need.

Ratings below: H good, M medium, L weak on each axis (Risk H = low risk).

Decision Area 1: Measurement and Build Configuration

1A Release + existing timers

Quick Debug-vs-Release check with SLog1.

+ Minutes of work. − Integer FPS, noisy, no GPU time.

1B In-app frame-time instrumentation (recommended)

Release preset + scope timers, ring buffer, avg/p95/max, fixed benchmark path.

+ Roadmap item, repeatable, teaches stats. − No GPU time.

1C External profiler (Tracy, RenderDoc, Nsight)

Full CPU/GPU timelines.

+ Deepest visibility. − New dependency, overkill at 2 draws.

1D Skip measurement

Fix by code reading.

+ Fastest. − Debug distortion; stale cache skews baseline.

Recommend 1B (1A as first step), escalate to 1C for GPU questions. Confidence high.

Decision Area 2: CPU Chunk Cache

2A In-place fix

Fix branch, init bitmap, cache all faces, invalidate on edit, return reference, move reserve.

+ Small diff. − Still wrong layer; pipeline still runs each frame.

2B Dirty-flag chunk mesh (recommended)

Drop the Face cache; meshDirty set on edit and boundary neighbors; chunk-level frustum test only.

+ Removes stale/camera bugs by construction. − Full payoff needs Area 3.

2C Remove caching

Regenerate each frame, optimize the path.

+ Simplest. − Cost scales, drops caching theme. Fallback if Release is fast.

2D Versioned multi-LOD cache

Version counters + LOD slots.

+ Robust, LOD-ready. − Speculative; LOD is hard-coded 0.

Recommend 2B, staged: 2A's correctness subset as a stopgap if Area 3 is delayed. Confidence medium-high.

Decision Area 3: GPU-Side Mesh Ownership

3A Shared buffer, upload only when dirty

Persistent transfer buffer, growth policy.

+ Minimal change. − Camera motion changes visible set; any edit re-uploads all.

3B Per-chunk persistent GPU buffers (recommended)

Each chunk owns an SDL_GPUBuffer; rebuild only when dirty; draw per visible chunk.

+ Zero work for static chunks; edits touch one chunk. − N draws; buffer lifetime bookkeeping.

3C Per-chunk + indirect/multi-draw

Batched indirect draws, optional GPU culling.

+ Scales. − Complex; no evidence draw calls bottleneck.

3D Merged buffer + sub-allocator

Regions, dirty-region copies.

+ Few binds, partial updates. − Allocator/fragmentation for 4 chunks.

Recommend 3B. Size per-chunk buffers from real vertex counts with a regrow policy (guards F9 overflow). Confidence medium-high on direction, low on magnitude.

Decision Area 4: Hidden-Face Culling and Meshing

4A Fix and enable in-chunk culling

Fix z-guard typos (1467, 1473), enable flag.

+ Tiny change. − Border faces stay.

4B Neighbor-aware cross-chunk culling (recommended)

Emit a face only if neighbor is air, via chunkMap for borders; chunk-local vertices; dirty neighbors on edit.

+ Removes all hidden faces. − Cross-chunk coupling.

4C Greedy meshing

Merge coplanar quads.

+ Fewest triangles. − Needs tiling/atlas; shallow terrain limits merging.

4D Indexed/compact vertices

4 verts + 6 indices per face, packed attributes.

+ Less bandwidth. − Shader changes; largely obviated by Area 3.

Recommend 4B (4A is its first half). Assumes air outside the loaded world. Confidence medium.

Decision Area 5: Chunk Data Layout

5A Keep optional<Object> (recommended now)

Optionally add cached isEmpty.

+ Zero risk. − ~160 KiB/chunk, poor locality.

5B Compact block ids + registry

uint8/16 ids, properties by lookup.

+ ~100x smaller, faster neighbor checks. − Broad refactor. Adopt when triggered.

5C Hybrid ids + sparse state table

+ Flexible. − Two representations, no need yet.

5D RLE / octree

+ Tiny memory. − Complex random access; overkill.

Recommend 5A now, 5B when triggered (measured memory or gen time, neighbor lookups in profile, or streaming). Confidence medium.

Recommended Approach

  1. Release/RelWithDebInfo preset + per-stage timers + benchmark path; record baseline (1A → 1B).
  2. Stopgap if needed: invalidate on edit, stop caching a frustum subset, initialize the bitmap.
  3. Replace the CPU Face cache with dirty-flag chunk meshes; chunk-level frustum test (2B).
  4. Per-chunk persistent GPU buffers, pooled transfer buffer, regrow policy (3B).
  5. Neighbor-aware culling with neighbor dirtying (4B); re-measure.
  6. Hold layout (5A); revisit 5B, 4C, 4D, 3C/3D only on measured triggers.

Rationale: the cache is in the wrong layer and the frame pays for full regeneration and re-upload; per-chunk GPU meshes with dirty flags remove that cost while deleting code, then neighbor culling shrinks each mesh. Measuring first avoids optimizing Debug artifacts.

Trade-offs accepted: multi-step OnRender refactor, cross-chunk coupling, N draw calls, bloated block storage.

Assumptions: edits are rare; Release frames are CPU-bound on mesh/upload; SDL3 GPU handles per-chunk buffers cheaply; 4-chunk scale stays small. If Release is GPU-bound or well under budget, stop after step 1 and the bug fixes (2C becomes reasonable). If edits become frequent, revisit 3D.

Confidence: medium.

Why not the others
  • 1A alone too coarse; 1C premature dependency; 1D unvalidated and the stale cache distorts baselines.
  • 2A alone leaves the pipeline running each frame; 2C loses headroom (valid fallback if Release is fast); 2D needs real LOD.
  • 3A rebuilds on camera motion and re-uploads all on any edit; 3C no evidence of draw-call bottleneck; 3D allocator complexity without scale need.
  • 4A alone is a subset of 4B; 4C needs tileable textures/atlas; 4D mostly bandwidth, largely obviated by Area 3.
  • 5B/5C/5D now: refactor cost exceeds current benefit at 4 chunks.
Deferred ideas
  • Real LOD with hysteresis and multi-LOD storage (F10).
  • Occlusion culling (commit message claims it; HEAD has none).
  • Texture atlas/array, mipmaps, duplicate sampler cleanup, blend review (F14).
  • Threaded chunk generation/meshing; streaming/eviction.
  • World-gen fixes: noise ignoring chunk offset, no heightmap cache (F17).
  • Small recomputes: dirty-flag frustum/view/proj, constexpr gravity dir, DDA chunk pointer reuse, unordered_map/last-chunk cache, Int3 hash (F11-F13).
  • Concurrency review: par_unseq atomics, E-key edit vs render (F15).
  • Unrelated bugs: double SDL_DestroySurface (951, 1062), atPos.y used for z (1192), dead line pass, integer FPS averaging.
  • Lighting/AO and GPU-driven culling.
