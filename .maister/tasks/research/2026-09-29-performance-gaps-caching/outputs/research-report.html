Caution: nothing was profiled. All impact ratings are heuristic. The build sets no optimization flags, so a Debug build likely inflates STL copy/allocation costs. Measure in Release first.

TL;DR

  • The only cache (per-chunk CPU list of world-space Faces) is broken: inverted branch (App.cpp:1418), never invalidated, and it bakes in the first frame's frustum-culled subset.
  • Even on a hit, each frame deep-copies, re-flattens, regenerates 60 B vertices and re-uploads the whole scene via a new transfer buffer; no per-chunk GPU mesh exists.
  • Hidden-face culling, LOD and occlusion are absent or disabled; no optimization build config.

Key Decisions

  • Measure in Release with frame-time stats first — every ranking is unmeasured.
  • Fix cache correctness first (low effort) — a stale or camera-dependent cache blocks any caching strategy.
  • Then per-chunk persistent GPU meshes with a dirty flag — removes copy/flatten/upload churn together.
  • Then neighbor-aware hidden-face culling — largest expected geometry reduction.

Open Questions / Risks

  • Real build type behind the only FPS claim (79→89, commit 9274f71) is unknown, likely Debug.
  • All struct sizes are estimates (no sizeof run).
  • Runtime effect of the inverted branch and of the vertex-buffer overflow risk not run.
  • Commit f36f85d says "Occlusion culling done" but HEAD has none.

Key insights

Cache alone will not help
Hit path still copies, flattens, regenerates and uploads. High confidence.
Camera-dependent cache is wrong
Cache the full chunk mesh; cull at chunk/draw level. High.
Per-chunk GPU meshes
Highest leverage; subsumes copy/flatten/upload. Direction high, magnitude unknown.
Hidden-face culling
Likely biggest geometry cut; terrain is shallow so density-dependent. Medium.
Build-type confound
Past "optimization" claims likely measured unoptimized. Medium.
Worldgen/raycast/math minor
Matter only with streaming or larger worlds. Medium.

Contradictions and discrepancies

  • Occlusion culling: culling-lod finds none; commit f36f85d says "Occlusion culling done". grep of src finds no "occlu"; treated as absent at HEAD (Medium).
  • Reserve size: ~1.7 MB vs ~3.5 MB per chunk per frame; both unmeasured estimates, same order of magnitude.
  • Chunk map: one gatherer says unordered_map; others and ChunkManager.h:41 say std::map.
  • Vertex buffer: resize/WaitForGPUIdle path is dead (flag false); overflow on growth is the live risk.

SWOT

Strengths
2 draw calls; cheap correct chunk frustum test; race-free per-chunk parallel meshing; static GPU resources created once.
Weaknesses
Broken cache; full re-upload per frame; heavy per-block data; no measurement.
Opportunities
Per-chunk GPU meshes, hidden-face culling, compact vertices, Release + LTO, real LOD.
Threats
Buffer overflow on growth; stale geometry after edits; unbounded memory as world scales.
