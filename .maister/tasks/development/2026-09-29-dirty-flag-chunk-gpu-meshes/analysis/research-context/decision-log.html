ADR-001: In-app per-stage timers and benchmark path without build-config change Accepted

Context. Nothing has been profiled; Debug artifacts likely inflate copy/STL costs. The user chose no build-config change and no new dependencies. (alternatives)

Decision drivers. Each change justified by data; dependency-free; roadmap profiling item; learning value; no CMake/preset changes.

Considered options. 1A Release preset + existing timers; 1B in-app per-stage timers; 1C external profiler; 1D no measurement.

Decision outcome. 1B without the Release preset: repeatable avg/p95/max per stage with a fixed benchmark camera path. Timings are relative-only if the build is Debug.

Good. Repeatable before/after comparison; permanent cheap instrumentation.

Bad. Debug timings may misrank stages; CPU-only (no GPU time); timers perturb tiny stages.

ADR-002: Replace the Face cache with a per-chunk dirty flag Accepted

Context. Chunk::cache holds CPU world-space Faces, is inverted (App.cpp:1418), never invalidated and camera-dependent; frames still copy, flatten, regenerate and upload. The cache is in the wrong layer. (alternatives)

Decision drivers. Correctness by construction; alignment with GPU ownership; less code; blocks change rarely.

Considered options. 2A in-place fix; 2B dirty-flag chunk mesh; 2C no caching; 2D versioned multi-LOD cache.

Decision outcome. 2B: meshDirty plus chunk-level frustum culling; remove isValidCache, cachedBlockPresence, per-block frustum test. The 2A correctness subset is an optional stopgap only if later stages are delayed.

Good. Removes stale/camera-dependent bugs; net code reduction; edits touch one chunk plus boundary neighbors.

Bad. Touches edit path and OnRender together; full payoff only with ADR-003; dirty-flag safety versus parallel meshing unverified.

ADR-003: Per-chunk persistent GPU vertex buffers Accepted

Context. Every frame builds one merged vertex array and uploads it via a new transfer buffer into a buffer sized once (overflow risk; resize path dead since canCreateVertexBufferEveryFrame=false). (alternatives)

Decision drivers. Zero work for static chunks; camera motion must not rebuild; fix overflow risk; simplicity at 4 chunks.

Considered options. 3A shared buffer upload-when-dirty; 3B per-chunk persistent buffers; 3C indirect/multi-draw; 3D sub-allocator.

Decision outcome. 3B with pooled transfer buffer and capacity + regrow policy (geometric growth from actual vertex counts, deferred release of replaced buffers, release on unload).

Good. Zero upload on clean frames; edits upload one chunk; covers overflow and transfer-buffer churn.

Bad. N draw calls; buffer lifetime bookkeeping; per-chunk offset needed for chunk-local vertices; magnitude unmeasured.

ADR-004: Neighbor-aware cross-chunk face culling Accepted

Context. Every block emits 12 faces; chunkFaceCulling is false and z-neighbor guards use x (App.cpp:1467, 1473). Terrain is shallow, so savings are density-dependent. (alternatives)

Decision drivers. Largest geometry cut for modest machinery; smaller meshes cut uploads; border correctness.

Considered options. 4A in-chunk only; 4B neighbor-aware; 4C greedy meshing; 4D indexed/compact vertices.

Decision outcome. 4B: fix z-guard typos first, chunk-local vertices, neighbors via ChunkManager, neighbor dirtying on boundary edits. Unloaded-neighbor policy must be stated in the spec; recommended default is air so world-edge faces stay visible.

Good. Removes interior hidden faces including at borders; correct by construction with neighbor dirtying.

Bad. Cross-chunk coupling; boundary policy affects world-edge visuals; greedy/indexed deferred.

ADR-005: Keep std::optional<Object> block storage for now Accepted

Context. Per-block optionals (~160 KiB per chunk by estimate) give poor locality, but no evidence memory or generation time limits at 4 chunks. (alternatives)

Decision drivers. Avoid broad refactor for small payoff; low risk with zero tests; keep option open.

Considered options. 5A keep; 5B compact ids; 5C hybrid; 5D RLE/octree.

Decision outcome. 5A. Revisit 5B when measured chunk memory or worldgen time matters, mesher neighbor lookups show in profiles, or streaming starts.

Good. Zero risk and effort now; narrow block-access interface eases a later swap.

Bad. Continued bloat and poor locality; slower neighbor checks than compact ids.
