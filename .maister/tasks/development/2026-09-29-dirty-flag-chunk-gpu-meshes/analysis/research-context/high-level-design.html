TL;DR

  • Replace the broken CPU Face cache and per-frame full-scene rebuild/upload with per-chunk dirty-flag meshes owned on the GPU (one persistent SDL_GPUBuffer per chunk, rebuilt only when dirty).
  • Chunk-level frustum culling replaces per-block culling; neighbor-aware hidden-face culling shrinks meshes; boundary edits dirty neighbor chunks.
  • Staged order: measure, dirty flag, GPU buffers, neighbor culling. Block storage left alone.
  • Dependency-free (SDL3 + stdlib). Confidence medium: nothing profiled.

Key Decisions

  • Measurement: in-app timers + benchmark path, no build-config change; relative-only if Debug (ADR-001).
  • Dirty flag replaces Face cache (ADR-002).
  • Per-chunk persistent GPU buffers, pooled transfer, regrow policy (ADR-003).
  • Neighbor-aware cross-chunk culling, chunk-local vertices, stated boundary policy (ADR-004).
  • Keep std::optional<Object> for now (ADR-005).

Open Questions / Risks

  • Magnitudes unmeasured; Debug timings are relative-only and cannot settle absolute questions (e.g. GPU-bound or not).
  • Thread safety of E-key edits vs parallel meshing unverified; dirty flag must be race-free.
  • Deferred release of GPU buffers still referenced by in-flight frames.
  • Unloaded-neighbor boundary policy (air vs solid) must be stated.
  • Per-chunk draw calls may need revisiting if chunk count grows.
  • Toolchain mismatch (MinGW logs vs MSVC-triplet vcpkg): real build may differ.

Design Overview

SDL_3DR is a single-executable C++23 voxel renderer on SDL3 GPU/Vulkan. Its only cache (Chunk::cache, CPU world-space Faces) is inverted, never invalidated and camera-dependent, and every frame still copies, flattens, regenerates 60 B vertices and re-uploads the whole scene through a fresh transfer buffer. Beneficiary: the single developer (frame headroom plus learning goals).

The chosen approach moves the cache to the GPU layer. Each Chunk gains meshDirty and a GPU mesh handle. A single-threaded remesh step regenerates only dirty chunks (chunk-local, exposed faces only, consulting neighbors), uploads via a pooled transfer buffer, and clears the flag. Rendering frustum-tests whole chunks and draws one buffer per visible chunk. A FrameProfiler times each stage; a fixed benchmark path makes runs comparable.

Data Flow

  1. Generation or E-key edit changes blocks; setBlock sets meshDirty on the chunk and, on a boundary cell, on the adjacent chunk.
  2. Frame start: frustum computed; per-chunk AABB test gives the visible set.
  3. Remesh (single-threaded, before render pass): dirty chunks are meshed (chunk-local exposed faces, neighbors read via ChunkManager), uploaded through the pooled transfer buffer in one copy pass, count/capacity updated, flag cleared.
  4. Render pass: per visible non-empty chunk, set offset, bind buffer, draw. No CPU vertex work for clean chunks.
  5. FrameProfiler times each stage and reports periodically.

Stage 2 keeps the old scene-wide upload but regenerates CPU vertices only for dirty chunks.

Integration Points

  • App::OnRender: largest change; replaces cache lookup, flatten, Face-to-Vertex3D regeneration and the single scene upload.
  • Edit path (E-key): must call dirty marking.
  • ChunkManager: neighbor accessor by chunk coordinate (existing chunkMap); unload hook releases GPU buffers.
  • Shaders/pipeline: chunk-local vertices need a per-chunk translation; Vertex3D layout can stay.
  • SDL GPU: buffer create/release, transfer map, copy pass, deferred release; no new dependencies.
  • Logging/UI: profiler output via existing logging macros or SDL3_ttf.
  • Threading: std::execution::par meshing only if each task owns its output and the dirty flag is not raced.

Concrete Examples

1. Static view. Given no edits, when a frame renders, then no chunk is remeshed and no upload occurs; remesh/upload stages read ~0 ms; draws equal visible chunk count.
2. Border edit. Given a block removed on the boundary between chunks A and B, when the next frame runs, then A and B are remeshed and uploaded once, new faces appear on both sides, other chunks untouched.
3. Buffer growth. Given a chunk's vertex count exceeds capacity, when remeshed, then a larger buffer is allocated (old one released after in-flight frames complete) and rendering continues without overflow.

Out of Scope

  • Build-config changes (Release presets, LTO); external profilers (Tracy, RenderDoc, Nsight).
  • Greedy meshing, indexed/packed vertices, indirect/multi-draw, sub-allocated buffer, atlas/mipmaps.
  • Compact block ids, RLE/octree storage.
  • Real LOD, occlusion culling, streaming/eviction, threaded generation, lighting/AO.
  • World-gen fixes and unrelated bugs (double SDL_DestroySurface, atPos.y for z, empty line pass, integer FPS averaging).

Success Criteria

  • Clean frames do zero remesh and zero upload (profiler-verified).
  • Camera motion alone triggers no rebuild or upload.
  • An edit remeshes only the edited chunk plus boundary neighbors, with no stale or missing geometry.
  • Scene vertex count drops after neighbor culling with no border holes.
  • Frame time (avg and p95) on the benchmark path improves vs stage-0 baseline within the same build configuration.
  • No vertex buffer overflow on mesh growth.
